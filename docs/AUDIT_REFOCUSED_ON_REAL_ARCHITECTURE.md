## 📌 РЕАЛЬНАЯ АРХИТЕКТУРА СИСТЕМЫ

### Основной поток (ПРИОРИТЕТ 1):

```
1. Загрузка отчётов (Reports)
   ├─ От агрегаторов
   └─ Содержат income_items с суммами за потоки

2. Расчёт роялти между артистами
   ├─ Если Artist на фиче → получает свою долю (track_to_percentage)
   └─ Если Partner → берёт только по artist.percentage

3. Формирование инвойсов
   └─ На основе invoice_items (доходы)

4. Начисление на основе отчётов
   └─ Распределение денег между артистами

5. Формирование выплат
   └─ Платежи артистам
```

### 2 ТИПА АРТИСТОВ:

#### 🎤 ARTIST:
```
- Может быть автором трека
- Может быть на фиче (feature) в чужих треках
- Проценты берутся из: track_to_percentage
  └─ Индивидуальные проценты для КАЖДОГО трека
  └─ Может быть разные для разных типов (автор, фич, и т.д.)
- Ключевая логика:
  └─ Если ii.artist_id = artist.id → это его трек (100% или его %)
  └─ Если ii.from_artist_id = artist.id → это его доля от лейбла
```

#### 🤝 PARTNER:
```
- Более простой расчёт
- Рассчитывается только паблишинг и дистрибуция
- Проценты берутся из: artist.percentage (одно поле!)
- Ключевая логика:
  └─ artist.percentage применяется ко всем его доходам
```
